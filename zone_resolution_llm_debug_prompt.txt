================================================================================
IMPLEMENTATION PROMPT: Zone Resolution Fix + LLM Debug Logging
================================================================================

CONTEXT
-------
The career path scoring system (backend/services/path_scoring.py) has a persistent
problem: zone resolution always returns (zone=1, resolved=False, reliable=False),
which sets zone_w=0.0 on every score. This means the entire final score is driven
only by skill centroid similarity, producing compressed results (52-60% for all roles).

The LLM normalization function _normalize_title_for_onet already exists in
path_scoring.py but it's unclear whether:
  (a) openai_client is actually being passed through to _resolve_current_zone
  (b) the LLM is returning a title O*NET can find
  (c) O*NET is returning results for the normalized title

There is also a _generate_search_terms function whose LLM output is unknown —
we don't know what occupation titles it's actually generating, which is causing
wrong candidates to appear (Remote Sensing Scientists, Bioinformatics Scientists)
and correct ones to be missing (Software Developers, Information Security Analysts).

GOAL
----
1. Fix zone resolution so "Founder & Full Stack Engineer" successfully resolves
   to a zone via LLM normalization.
2. Add a comprehensive LLM debug log file (llm_debug.txt, written alongside
   scoring_debug.txt) that captures every LLM input prompt, raw response, and
   parsed output for each scoring invocation — so we can see exactly what is
   going into and coming out of the LLM at each step.

================================================================================
CHANGE 1 — Verify openai_client is reaching _resolve_current_zone
================================================================================

In score_paths(), trace the call chain:

  score_paths(user_profile, onet_client, openai_client=None)
    → _resolve_current_zone(profile, onet_client, openai_client)
      → _normalize_title_for_onet(raw_title, openai_client)

Confirm that wherever score_paths is called in app.py, openai_client is being
passed as a non-None value. If the call looks like:

  scored = score_paths(user_profile, onet_client)          # WRONG — no client

Change it to:

  scored = score_paths(user_profile, onet_client, openai_client)

The openai_client should come from _get_openai_client() in path_narrative.py.
This is the most likely reason zone resolution is silently failing.


================================================================================
CHANGE 2 — Improve _normalize_title_for_onet prompt and add fallback chain
================================================================================

The current single-attempt normalization may return a title O*NET still can't
find. Replace it with a two-attempt fallback chain:

  Attempt 1: LLM returns a specific normalized title (e.g. "Software Developer")
             → search O*NET → if results found, return (zone, code, True)

  Attempt 2: If attempt 1 fails, LLM returns the BROAD occupational category
             (e.g. "Software Developers" → O*NET standard plural form)
             → search O*NET → if results found, return (zone, code, True)

  Fallback: return (1, None, False) as before

Update the prompt to make O*NET-style titles more likely:

  UPDATED PROMPT for _normalize_title_for_onet:
  -----------------------------------------------
  "Map this job title to a standard O*NET occupation title.
  Use exact O*NET-style titles (e.g. 'Software Developers', 'Web Developers',
  'General and Operations Managers', 'Computer and Information Systems Managers').
  Use plural form as O*NET uses plural occupation names.
  No explanation. Output the title only.

  Examples:
    'Co-Founder & CTO' → 'Computer and Information Systems Managers'
    'Founder & Full Stack Engineer' → 'Software Developers'
    'Senior Data Analyst' → 'Data Scientists'
    'Head of Growth' → 'Marketing Managers'

  Input: {raw_title}
  Output:"

Add a second attempt with a simpler prompt if the first normalized title
returns no O*NET results:

  FALLBACK PROMPT:
  -----------------
  "What is the closest standard job category for: {raw_title}
  Reply with only a common job title, one of: Software Developers,
  Web Developers, Data Scientists, Registered Nurses, Accountants,
  Marketing Managers, Sales Representatives, Teachers, Engineers.
  Output:"

CHANGE 3 — Create llm_debug.txt logging infrastructure
================================================================================

Add a module-level LLM debug log list that accumulates entries during a single
score_paths invocation, then writes to file at the end.

At module level in path_scoring.py:

  _LLM_DEBUG_LOG: list[str] = []

Add a helper:

  def _llm_log(section: str, content: str) -> None:
      """Append a timestamped entry to the LLM debug log."""
      _LLM_DEBUG_LOG.append(f"\n{'='*60}\n{section}\n{'='*60}\n{content}")

Add a writer (called at the end of score_paths alongside _print_scoring_debug):

  def _write_llm_debug_log() -> None:
      import os as _os
      out_path = _os.path.join(_os.path.dirname(__file__), "..", "..", "llm_debug.txt")
      out_path = _os.path.normpath(out_path)
      with open(out_path, "w", encoding="utf-8") as f:
          f.write("\n".join(_LLM_DEBUG_LOG))
      _LLM_DEBUG_LOG.clear()

At the start of score_paths, clear the log:

  _LLM_DEBUG_LOG.clear()


================================================================================
CHANGE 4 — Add _llm_log calls at every LLM interaction point
================================================================================

LOG POINT A — Zone normalization attempt in _normalize_title_for_onet:

  _llm_log(
      "ZONE RESOLUTION — Title Normalization",
      f"Raw title input : {raw_title!r}\n"
      f"Prompt sent     :\n{prompt_text}\n"
      f"Raw LLM response: {resp.choices[0].message.content!r}\n"
      f"Parsed output   : {normalized!r}"
  )

  On exception:
  _llm_log(
      "ZONE RESOLUTION — Title Normalization FAILED",
      f"Raw title: {raw_title!r}\n"
      f"Error    : {exc!r}"
  )

LOG POINT B — Zone resolution result in _resolve_current_zone:

  After each _search_and_resolve attempt, log:
  _llm_log(
      "ZONE RESOLUTION — O*NET Search Result",
      f"Search term     : {title!r}\n"
      f"O*NET found     : {bool(result)}\n"
      f"Resolved zone   : {result[0] if result else 'N/A'}\n"
      f"Resolved code   : {result[1] if result else 'N/A'}"
  )

  Final resolution outcome:
  _llm_log(
      "ZONE RESOLUTION — Final Outcome",
      f"zone={current_zone}  resolved={zone_resolved}  reliable={zone_is_reliable}\n"
      f"onet_code={current_code!r}"
  )

LOG POINT C — Search term generation in _generate_search_terms:

  _llm_log(
      "SEARCH TERM GENERATION — LLM Input",
      f"Current title: {profile.current_title!r}\n"
      f"Skills ({len(profile.skills)}): {', '.join(s.name for s in profile.skills)}\n\n"
      f"Full prompt:\n{prompt}"
  )

  After LLM response:
  _llm_log(
      "SEARCH TERM GENERATION — LLM Output",
      f"Raw response : {raw_response!r}\n"
      f"Parsed terms : {parsed_terms}"
  )

  On parse failure:
  _llm_log(
      "SEARCH TERM GENERATION — Parse Failed, Using Fallback",
      f"Raw response : {raw_response!r}\n"
      f"Error        : {exc!r}\n"
      f"Fallback     : {fallback_terms}"
  )

LOG POINT D — O*NET candidate search results:

  After each search term:
  _llm_log(
      f"CANDIDATE SEARCH — Term: {term!r}",
      f"Results ({len(results)}): {[o.title for o in results]}"
  )

  After all searches, total candidate pool:
  _llm_log(
      "CANDIDATE POOL — Final",
      f"Total candidates: {len(candidates)}\n"
      + "\n".join(f"  [{o.code}] {o.title}" for o in candidates)
  )

LOG POINT E — Behavioral profile composition:

  _llm_log(
      "BEHAVIORAL PROFILE — Composed String",
      f"archetype      : {profile.archetype!r}\n"
      f"focus_type     : {profile.focus_type!r}\n"
      f"manager_match  : {profile.manager_match!r}\n"
      f"work_style_tags: {profile.work_style_tags}\n\n"
      f"Composed string:\n{behavioral_profile or '(None — no assessment data)'}"
  )

LOG POINT F — Per-candidate embedding results (top 5 only to keep log readable):

  After scoring each candidate, accumulate results. After all candidates scored,
  log the top 5 by final score:

  _llm_log(
      "CANDIDATE SCORES — Top 5 Detail",
      "\n".join(
          f"  [{d['code']}] {d['title']}\n"
          f"    centroid={d['centroid_score']:.4f}  coverage={d['coverage_score']:.4f}\n"
          f"    work_style={d['work_style_score']:.4f}  zone={d['zone_score']:.4f}\n"
          f"    final={d['final_score']:.4f}"
          for d in top5_debug
      )
  )
