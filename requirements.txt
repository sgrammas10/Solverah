# Direct dependencies, pinned.
#
# Unpinned, every CI run and every deploy resolved to whatever was latest at
# that moment, so a broken or compromised release would land with nothing in
# the way -- and a new CVE could appear in a build that had changed nothing.
# Versions below are the set pip resolved for the CI target (cp311,
# manylinux2014_x86_64) and were checked against OSV with zero hits.
#
# Transitive dependencies are still unpinned. Closing that gap means a real
# lock file -- `pip-compile` (pip-tools) from a requirements.in -- which is a
# larger change than this one. The pip-audit gate in CI is the backstop: it
# audits the whole installed environment, so a bad transitive version fails
# the build rather than shipping quietly.
#
# Bumping a pin: change it here, let CI run pytest + pip-audit, and read both.

# Rate-limit + cache backend. Without it Flask-Limiter falls back to memory://,
# which counts per gunicorn worker and resets on every deploy -- so the auth
# limits in app.py are N-workers times looser than configured and an attacker's
# budget is cleared by any redeploy. security.py degrades loudly rather than
# failing boot when this is absent, but production needs it installed AND
# REDIS_URL set. Pure-Python wheel, no build step.
