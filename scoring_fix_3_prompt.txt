PROBLEM 2 — Coverage score has no differentiation (all 0.4000 or similar flat values)
----------------------------------------------------------------------------------
After filtering the pool, coverage still needs to produce different values per role.

ROOT CAUSE of flat coverage:
  The top-5 role profile items most similar to the ROLE's own centroid tend to be
  the same abstract competencies for all tech roles (Python, programming, data analysis).
  If the user matches 2 of those 5 for every tech role, everyone gets 0.4000.

CORRECT FIX for coverage — use role centroid vs USER skills (not a full direction flip):
  Instead of: "top-K items in the ROLE profile closest to the ROLE centroid"
  Use:        "top-K items in the ROLE profile closest to the USER centroid"

  This asks: "What does this role offer that is most relevant to THIS user?"
  and then checks whether the user actually has those skills.

  _user_centroid = mean of all user skill embeddings (precomputed once per score_paths call)

  For each candidate role:
    top_k_role_items = top K role profile items sorted by sim(item_embedding, user_centroid)
    coverage = fraction of top_k_role_items where sim(item, any user skill) >= threshold

  This is different from the (broken) "user direction" approach in round 2.
  Round 2 mistake: took top-K USER skills most similar to role centroid.
  This fix:        takes top-K ROLE items most similar to USER centroid.

  Why this works:
    - Software Developers profile contains React, JavaScript, Python, TypeScript, SQL
    - These items are close to the user's centroid (user HAS those skills)
    - So top-5 role items for Software Developers = [React, JS, Python, TS, SQL]
    - User matches all 5 → coverage = 1.0

    - Bioinformatics Scientists profile contains genomics, molecular biology tools
    - These items are FAR from the user's centroid
    - top-5 role items = [genomics tools, lab software, etc.]
    - User matches 0/5 → coverage = 0.0

  This correctly differentiates tech roles from research roles without the round 2 problem.

  Implementation:
    # Precompute user centroid once in score_paths before candidate loop
    user_skill_embeddings = [_EMBED_CACHE[s.name] for s in profile.skills
                             if s.name in _EMBED_CACHE]
    user_centroid = np.mean(user_skill_embeddings, axis=0)

    # In _coverage_score function:
    def _coverage_score(user_centroid, role_item_embeddings_and_names,
                        user_skill_embeddings, k=5, threshold=_EMBED_THRESHOLD):
        # Top-K role items closest to the user's centroid
        sims = [(cos_sim(item_emb, user_centroid), item_name, item_emb)
                for item_emb, item_name in role_item_embeddings_and_names]
        top_k = sorted(sims, reverse=True)[:k]

        # Check if user actually has each of those top-K role items
        matched = 0
        for _, item_name, item_emb in top_k:
            best_match = max((cos_sim(item_emb, u_emb) for u_emb in user_skill_embeddings),
                             default=0.0)
            if best_match >= threshold:
                matched += 1

        return matched / k
