FIX 1 — Zone resolution (CRITICAL — fixes the biggest lever in the formula)
================================================================================

The llm_debug.txt from the previous run showed NO "ZONE RESOLUTION — Title
Normalization" log entry, which means the LLM normalizer is still not being called.

The code path must be:
  Step 1: search O*NET with raw title → found "Engineers, All Other" → reliable=False
  Step 2: IF reliable=False AND openai_client is not None → call _normalize_title_for_onet
  Step 3: search O*NET with normalized title → should find "Software Developers"

The bug is in step 2: the code is NOT calling _normalize_title_for_onet when
reliable=False. Add this logic explicitly in _resolve_current_zone:

  def _resolve_current_zone(profile, onet_client, openai_client=None):
      raw_title = profile.current_title

      # Attempt 1: raw title
      zone, code, reliable = _search_and_zone(raw_title, onet_client)
      _llm_log("ZONE — Raw attempt", f"title={raw_title!r} zone={zone} reliable={reliable}")

      if reliable:
          return zone, code, True

      # Attempt 2: LLM-normalized title (runs even if attempt 1 found something unreliable)
      if openai_client is not None:
          normalized = _normalize_title_for_onet(raw_title, openai_client)
          _llm_log("ZONE — LLM normalized to", repr(normalized))
          if normalized:
              zone2, code2, reliable2 = _search_and_zone(normalized, onet_client)
              _llm_log("ZONE — Normalized attempt", f"zone={zone2} reliable={reliable2}")
              if zone2 and zone2 > 1:
                  return zone2, code2, True

      return 1, None, False

VERIFY: after this fix, llm_debug.txt MUST contain a "ZONE — LLM normalized to" entry.
If it doesn't, openai_client is still None when score_paths is called — check app.py.
