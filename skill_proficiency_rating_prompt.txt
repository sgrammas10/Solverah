================================================================================
IMPLEMENTATION PROMPT: Skill Proficiency Rating — Pre-Path Intelligence Modal
================================================================================

PROBLEM
-------
All user skills are treated as equally weighted (all "beginner"). The scoring
algorithm can't distinguish "I build React apps daily" from "I tried ARIMA once".
For a full-stack founder with both core web skills and exploratory ML skills,
this causes research scientist roles to rank above software developer roles.

SOLUTION
--------
Prompt users to rate each skill as Beginner / Intermediate / Advanced before
entering Path Intelligence. Use those ratings as multipliers in the user centroid
computation. Core skills dominate; exploratory skills de-emphasize.

This is optional but highly suggested — users can skip and still see results,
with a persistent nudge banner encouraging them to rate later.

  CTA button: "Rate skills" → opens the proficiency modal

  Style: soft info/warning tone (not error red)

RE-OPEN MODAL:
  Small "Edit skill ratings" link or icon button in the Path Intelligence header/settings area.
  Clicking it opens the proficiency modal with current ratings pre-populated.
  After saving, Path Intelligence re-scores immediately (trigger a re-fetch of results).

BACKEND CHANGES
================================================================================

1. PROFICIENCY WEIGHT IN USER CENTROID (path_scoring.py)

   The user centroid is currently the unweighted mean of all skill embeddings.
   Change it to a weighted mean using proficiency multipliers:

     PROFICIENCY_WEIGHTS = {
         "beginner":     1.0,
         "intermediate": 2.0,
         "advanced":     3.0,
     }

   Implementation in score_paths() (before candidate scoring loop):

     weighted_embeddings = []
     for skill in profile.skills:
         if skill.name not in _EMBED_CACHE:
             continue
         weight = PROFICIENCY_WEIGHTS.get(skill.proficiency.lower(), 1.0)
         emb = _EMBED_CACHE[skill.name]
         weighted_embeddings.extend([emb] * int(weight))
         # OR: use numpy weighted average directly:
         # weighted_sum += weight * emb; total_weight += weight
     user_centroid = np.mean(weighted_embeddings, axis=0)

     Preferred: use numpy weighted average (more precise than repeating vectors):
     emb_matrix = np.array([_EMBED_CACHE[s.name] for s in profile.skills
                             if s.name in _EMBED_CACHE])
     weights = np.array([PROFICIENCY_WEIGHTS.get(s.proficiency.lower(), 1.0)
                         for s in profile.skills if s.name in _EMBED_CACHE])
     user_centroid = np.average(emb_matrix, axis=0, weights=weights)

   EFFECT: A user with React=Advanced, TypeScript=Advanced, Python=Intermediate,
   ARIMA=Beginner, SARIMA=Beginner will have a centroid that heavily emphasizes
   React/TypeScript/Python and barely registers ARIMA/SARIMA. The research scientist
   roles that were winning due to ML skill contamination will drop significantly.

2. PROFICIENCY IN COVERAGE SCORE

   The coverage score checks whether the user "has" a skill that the role values.
   With proficiency weights, treat beginner-level skills as weaker evidence:

     For each user skill checked in coverage:
       effective_threshold = _EMBED_THRESHOLD + (1.0 - weight/3.0) * 0.05
       # Beginner skills need similarity >= 0.75 to count
       # Advanced skills need similarity >= 0.70 to count

   This is a small tweak — the weighted centroid does most of the heavy lifting.

3. UserProfile DATACLASS
   Ensure the `proficiency` field on each Skill object is correctly populated from
   the database when building the UserProfile for scoring. If it's currently
   hardcoded or defaulted to "beginner" in the profile construction code in app.py,
   fix it to read the actual stored proficiency value.

4. API ENDPOINT (if not already exists)
   PATCH /api/user/skills/proficiency
   Body: { skills: [{ name: "React", proficiency: "advanced" }, ...] }
   Updates proficiency for each named skill in the user's profile.
   Also sets skills_proficiency_confirmed = True on the user record.

   OR if skills are updated individually via existing endpoints, add
   skills_proficiency_confirmed handling to whatever endpoint marks proficiency.
