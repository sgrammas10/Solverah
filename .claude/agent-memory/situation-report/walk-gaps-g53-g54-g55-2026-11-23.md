Built 2026-11-23 (orchestrator dispatch, uncommitted at hand-off). Frontend only, no API change.

- **G53**: `EnvironmentReportPage` now asks for career status BEFORE question 1 (and before the
  resume prompt) when the profile shows no status the server could read. It mirrors
  `_live_career_status` client-side (`hasReadableCareerStatus`: stored status, or an experience
  `endDate` of Present/Current). PathIntelligencePage had already set the precedent for this mirror.
  The submit's `career_status_not_set` refusal stays as a backstop and keeps its "answers saved"
  copy. The page also waits for the profile query before it renders the intro. The return label is
  now "describing your job" ("Go back to describing your job?"); the old label was "your Situation
  Report". Router state goes through `careerStatusNavState(..., "environment_report")`, which is
  G43's subtitle key.
  **Why a client mirror and not a server flag:** a server flag on GET /me/situation-report would
  change the contract baseline and openapi/schema.ts, and Julie's Flask is --no-reload. The
  server check is still the authority.
- **G54**: `ToleranceWaitsNote` mounts only after a "nothing moved" re-read, and only then reads
  /me/trait-preferences. It shows the specific line only when `answered && tolerance_applied ===
  false`, the one pending case the client can see. Otherwise it shows a general line. Neither
  payload carries a timestamp, so a changed-but-already-applied tolerance cannot be detected.
- **G55**: the SituationReportPage gate copy now says "sixteen ... plus five optional ones".

**Open:** the docs/USER_SCENARIOS.md steps (S9.10a ~970, line ~88, S11.6 ~1161, ~1029, ~2294) still
describe the old behaviour. The walker chat edits that doc concurrently, so it was not edited here.
